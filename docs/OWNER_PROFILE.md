## Як працюємо
- **«Роби»** = обговорення закінчене, можна змінювати код/файли. **Без «Роби» — тільки
  обговорення, код не чіпати.**
- **Скріншоти й голосові** (перекладені в текст) — нормальний спосіб показати баг чи ідею;
  «живі» формулювання цитувати дослівно в документах як «слово власника».
- Пояснювати **«чому»**, а не лише результат.

## 🔴 Обов'язкове в КОЖНОМУ повідомленні
1. **Пояснення англійських термінів у дужках** українською — одразу після слова:
   `PR (pull request — запит на злиття змін)`, `deploy (публікація сайту)`.
   **Це важливіше за стислість.**
2. **Коротко.** Середні або менше середнього відповіді, по пунктах. Деталі — лише на
   «розкажи детальніше». Одна думка за раз.
3. **Контент для пересилання — одразу готовим блоком коду** (лист, текст, команда).
4. **Покрокові інструкції для ручних дій** (налаштування сервісів, секрети, SQL) —
   нумеровано, з точними назвами кнопок і прямими посиланнями, «напиши “зробив N”».

## Чого НЕ робити
- Не погоджуватись заради ввічливості — **сперечайся**, вказуй слабкі місця ідеї.
- Не давати довгих технічних пояснень без запиту.
- Не створювати нових правил самостійно — спершу спитати власника.
